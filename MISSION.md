# Mission: GitHub

## Why

Daniel wants his own projects to live somewhere real — published on GitHub, under his
own name, safe from a single laptop dying. Right now work sits in local folders that
nobody else can see and no backup protects. When this skill lands, shipping a project
means pushing it, and the work is visibly, permanently his.

## Success looks like

- Publishing a new project to GitHub from scratch, unaided, in under five minutes
- Every commit correctly attributed to his GitHub account, with the contribution graph to prove it
- Confidently making changes and pushing them without fear of "breaking" anything
- Recovering from mistakes — undoing a bad commit, restoring a deleted file — without panic
- A README on each repo that explains the project to a stranger
- Knowing when a repo should be private vs public, and how to switch

## Constraints

- **Total beginner.** New to both git and GitHub. No assumed vocabulary.
- **10–15 minute lessons.** One idea per lesson, sized to a single sitting.
- **macOS**, zsh, `git` 2.50.1, `gh` CLI 2.98.0 already installed.
- Solo workflow first. Team collaboration is later, not now.

## Out of scope

- Team collaboration: pull request review, protected branches, CODEOWNERS
- Open source contribution: forks, upstream etiquette
- GitHub Actions and CI/CD
- Rebasing, cherry-picking, and other history surgery
